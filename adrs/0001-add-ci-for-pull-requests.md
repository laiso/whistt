# ADR 0001: Pull Requestに継続的インテグレーションを導入する

- Status: Accepted
- Date: 2026-09-03

## Context

このリポジトリには、Pull Request（PR）に対して自動実行されるCIがない。

PR #10では、音声送信処理の共通化、バッファリング、フレーム分割、送信ペーシング、終了処理に加えて、OpenAI・Gemini・Metaの3つの通信経路が変更された。変更量は約1,300行であり、あるプロバイダ向けの修正が別のプロバイダやmacOSアプリ本体を壊していないことを、レビューだけで継続的に確認するのは難しい。

PR #10のブランチでは、手元で次の結果を確認できた。

- `swift test`: 54テスト、失敗0
- `make build`: macOSアプリのDebugビルド成功

ただし、これらは開発者が手元で実行した結果であり、GitHub上では自動チェックされていない。PR本文のテスト件数も現在の実数とずれる可能性があり、実行結果をマージ条件として利用できない。

## Decision

GitHub Actionsを使い、`main`を対象とするPRと`main`へのpushで、以下のチェックをmacOSランナー上で自動実行する。

### 1. Swift Packageのテスト

```sh
swift test
```

このチェックでは、以下を含む`WhisttCore`の回帰を検出する。

- 音声データのフレーム分割とバイト順序
- ready前のバッファリングと上限処理
- リアルタイム送信のペーシング
- 送信完了待ちと終了通知の順序
- セッション間の状態分離
- OpenAI・Gemini・Metaのプロトコル処理
- 環境変数ファイルの読み込み

### 2. macOSアプリのDebugビルド

```sh
make build
```

Swift Packageのテスト対象から除外されているUI、`AppDelegate`、APIキー設定、音声入力処理などを含め、アプリ全体がコンパイルできることを確認する。

## Implementation tasks

- [x] `.github/workflows/ci.yml`を追加する
- [x] `pull_request`と`push`の`main`ブランチを実行対象にする
- [x] macOSランナー上でリポジトリをチェックアウトする
- [x] `swift test`を実行するジョブを追加する
- [x] `make build`を実行するジョブを追加する
- [x] テストとビルドを別ジョブにし、失敗箇所をPR画面から判別できるようにする
- [x] 同じブランチへの追加push時に古い実行をキャンセルする
- [ ] CIを追加したPRで両ジョブが成功することを確認する
- [ ] GitHubの`main`ブランチ保護で両チェックを必須にする
- [ ] PR #10の説明にあるテスト件数を実行結果と一致させる

## Acceptance criteria

- PRを作成または更新すると、テストとアプリビルドが自動的に開始される
- いずれかが失敗した場合、PR画面で失敗したチェックとログを確認できる
- 両チェックが成功しない限り、`main`へマージできない
- APIキーなどのシークレットを登録しなくてもCIが実行できる
- CI内では外部の音声認識APIへ接続しない

## Consequences

### Positive

- PR作成者の自己申告に依存せず、テストとビルド結果を確認できる
- 複数プロバイダにまたがる変更の回帰をマージ前に検出できる
- Swift Packageだけでなく、macOSアプリ側のコンパイルエラーも検出できる

### Negative

- macOSランナーの実行時間とGitHub Actionsの利用枠を消費する
- XcodeやmacOSランナーの更新によって、アプリコードと無関係な失敗が発生する可能性がある
- ビルド生成物のキャッシュを使わない初期構成では、実行時間が長くなる可能性がある

## Out of scope

今回のCIでは、以下は自動化しない。

- 実際のマイクを使った録音
- OpenAI・Gemini・Metaへの実通信
- APIキーが必要なライブプローブ
- 10秒以上の発話によるMetaの切断問題の再現確認
- 署名、notarization、配布用Releaseビルド

これらは当面、リリース前または音声通信経路を変更した際の手動スモークテストとして扱う。将来、安定したモックまたは専用の検証環境を用意できた場合は、別のADRで自動化を検討する。
